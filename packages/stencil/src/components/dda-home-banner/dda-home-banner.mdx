# Home Banner

The `dda-home-banner` component is a full-viewport image or video carousel for landing pages. You
supply each slide as a `<slide>` element; the component adds previous and next buttons, slide
dots and, with `autoplay`, a pause button.

## Usage

### Vanilla JS

**From the CDN.** Replace `X.X.X` with the exact package version.

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@dubai-design-system/components-js@X.X.X/dist/dda/dda.css" />
<link rel="stylesheet" href="https://fonts.googleapis.com/icon?family=Material+Icons" />
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Material+Symbols+Outlined:opsz,wght,FILL,GRAD@20..48,100..700,0..1,-50..200" />
<script type="module">
  import { defineCustomElements } from 'https://cdn.jsdelivr.net/npm/@dubai-design-system/components-js@X.X.X/loader/index.es2017.js';
  defineCustomElements();
</script>

<dda-home-banner autoplay="true" interval="5000" aria_label="Highlights">
  <slide>
    <img src="/img/home-banner.jpg" alt="Aerial view of Dubai at sunset" />
    <div class="slide-wrap">
      <div class="slide-content">
        <h2>Digitalizing Life In Dubai</h2>
        <p>Pioneering and accelerating the pace of digital transformation in the city</p>
      </div>
    </div>
  </slide>
</dda-home-banner>
```

Without the Material Icons link, the carousel arrows render as the words `chevron_left` and
`chevron_right`.

**From npm with a bundler (Vite, Rollup).** Import the component file; it defines the element.

```js
import '@dubai-design-system/components-js/dist/dda/dda.css';
import '@dubai-design-system/components-js/dist/components/dda-home-banner.js';

const banner = document.querySelector('dda-home-banner');
banner.autoplay = true;
banner.interval = 7000;
```

## Slide structure

The banner is **slotted** — you supply the slides as markup. Each slide **must be a
`<slide>` element**; the component collects them with `querySelectorAll('slide')` and
anything else is ignored (you would get a banner with no slides and no dots).

Inside each `<slide>`, use `.slide-wrap` for the full-height flex wrapper and
`.slide-content` for the constrained content column:

```html
<dda-home-banner autoplay="true" interval="5000">
  <slide>
    <img src="assets/img/home-banner.jpg" alt="Aerial view of Dubai at sunset" />
    <div class="slide-wrap">
      <div class="slide-content">
        <h2>Digitalizing Life In Dubai</h2>
        <p>Pioneering and accelerating the pace of digital transformation in the city</p>
        <dda-button button_color="default-primary" size="lg">Call to action</dda-button>
      </div>
    </div>
  </slide>

  <slide>
    <video src="assets/video/skyline.mp4" autoplay muted loop playsinline></video>
    <div class="slide-wrap">
      <div class="slide-content">
        <h2>Explore More</h2>
        <p>Find the services you need</p>
      </div>
    </div>
  </slide>
</dda-home-banner>
```

Slides added or removed later are picked up automatically.

## Styling

<div style={{ padding: '12px 16px', borderLeft: '4px solid #0B273D', background: '#f4f6f8', margin: '16px 0' }}>

**Styling is delivered by the component, not by `dda.css`.**

The banner's layout CSS is bundled into the component's own JavaScript chunk and injected
into the page when the element upgrades. Loading the global `dda.css` and calling
`defineCustomElements()` is all that is required — do **not** link
`dist/collection/components/dda-home-banner/home-banner.css` separately.

If the banner renders as a normally-flowed image with the text spilling below it, check
these in order:

1. **You are on a release older than the fix.** Earlier versions required you to write
   `class="home-slider"` on the element yourself. The component now applies it. Upgrade,
   or add that class as a stopgap.
2. The slides are not `<slide>` elements.
3. The component has not upgraded — check that `defineCustomElements()` ran and that the
   loader script URL resolves.

## Accessibility

- The host exposes `role="region"` with `aria-roledescription="carousel"` and an
  `aria_label`, so screen-reader users can identify and skip the banner.
- Previous/next buttons and the slide dots are real `<button>` elements with accessible
  names, so the carousel is fully keyboard operable.
- When `autoplay` is on, a **pause/play** button is rendered — required by
  WCAG 2.2.2 (Pause, Stop, Hide) for content that moves automatically.
- Autoplay also suspends while the pointer is over the banner or keyboard focus is
  inside it, so it cannot move a slide out from under the user.
- Autoplay is disabled entirely when the user has `prefers-reduced-motion: reduce` set.
- Slides that are not current are marked `inert` and `aria-hidden`, so the keyboard
  cannot reach offscreen calls to action and screen readers do not read them.
- A visually hidden live region announces "Slide 2 of 3" on manual slide changes. It is
  silent while the carousel rotates on its own, so autoplay does not chatter.
- Give every slide `<img>` a meaningful `alt`; use `alt=""` if the image is decorative
  and the message is carried by `.slide-content`.
- **Slotted `<video autoplay>` is your responsibility.** The pause button stops the slide
  rotation, not media inside a slide. If you autoplay video, keep it `muted` and `loop`,
  or provide your own control, so the slide still satisfies WCAG 2.2.2.
